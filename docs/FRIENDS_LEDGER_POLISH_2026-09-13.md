# 朋友局记账优化与发布交接

日期：2026-09-13。分支：`codex/friends-ledger-polish`；开发基线：`5e0b4ea`。

本轮目标是减少记账和创建过程中的阻碍，保持可信流水与完整缓存体验。优先级仍是 **数据准确 > 体验 > 性能**。本轮未部署云函数、未上传小程序、未修改生产数据。

### 1. 在场成员互相代买

- `playerOpsShared !== false` 时，普通在场成员可为其他在场成员补买或加分；共享关闭仍仅房主操作。
- 旁观者不获得权限。新增代买路径拒绝已移出操作人或目标，不收紧原房主及自己买入的兼容调用。
- 撤销与移出仍仅房主；不顺带放开其他管理权限。
- 流水写实际操作人、被记录玩家、买入前后手数；幂等重放不新增流水。
- 目标此前已结算、记录仍进行中时，补买清除其原结算状态，`settledCount/checkedOutCount` 继续双写并一致。
- 关闭共享时前端不再提供普通成员自己买入等必然被云端拒绝的菜单。

### 2. 减少创建等待与误操作

- 已有有效资料时不再额外等待一次资料刷新；云端仍以用户集合确定实际身份资料。
- 缺资料时在创建页打开资料弹框；保存后继续创建，取消保留原表单，不绕行“我的”。加入流程的初始手数输入保留。
- 在异步身份读取之前锁定提交，捕获本次配置；按钮显示进行状态，不再叠加全屏 loading。
- 同一页面、同一账号、同一份表单重试复用操作号，配置改变后才换号。成功后跳转失败也复用已经确认的房间 ID。
- 云端创建、初始流水、操作回执同事务完成。缺回执是正常首次请求；读写异常必须让事务失败，不能当作缺回执继续创建。
- 首次响应保留旧字段并新增初始 `transactions`。跳转前缓存房间和全部初始流水；旧云函数没返回数组时保留兼容路径。
- 回执重放只返回已确认 ID 等结果，不返回可能过时的初始房间快照。
- 只在成功后保存本人的积分、盲注、换算与共享配置，不复用名称或成员，不新增“再开一局”。

边界：创建操作号目前保存在页面实例，不跨关闭页面或程序重启恢复；不能宣称所有未知结果在跨重启后都已自动处理。既有买入、结算待提交队列不受此变更影响。

### 3. 流水和文案

- 结束事件使用真实 `endedAt`，与所有流水统一倒序；结束后的修正、费用变更自然在其上方。
- 结束事件仅为展示派生，不写新交易、不回填历史、不宣称“全员已结算”；已有结束事件不重复生成。
- 费用摘要、账差显示和既定流水排版保持不变，不增加二级入口、额外确认或提醒。
- “改码/帮他改码/踢人”改为“修改结算/帮他修改结算/移出记录”。
- “买入次数/位置”改为“累计手数/座位”；原 `rebuys/position` 字段、分桶规则与旧返回值保留，仅前端单位改为“手”。
- 积分榜重算入口明确为“重新计算本季积分”，不再误导为清空原始积分。

### 4. 统计边界

- `calcSeasonScore` 和 `getSeasonView.myGames` 排除历史 `deletedAt` 记录；计算版本升为 6。
- 缺失或非法开始时间不能因为时长为 NaN 而误入赛季，原至少 20 分钟规则不变。
- 个人隐藏后的统计重算排除全局删除和本人已移出记录，仍重算最大赢亏等派生值。
- 个人隐藏只影响本人可见列表与个人统计，不改变其他用户统计或积分榜结果；赛季时长规则不额外施加于个人统计。
- 本轮没有执行任何生产历史重算、删除、清理或数据迁移。是否重算历史赛季需先只读核对，再单独授权。

## 性能约束与验证

未重写详情全局渲染架构，未增加骨架屏、分段替换流水、高频轮询或等待云分析的新链路。

本地 `npm run check`、`npm run lint`、`git diff --check` 已通过。重点用例包括：

- 普通成员代买、关闭共享、旁观者、已移出成员、重复操作号、结算后补买状态恢复。
- 创建并发重复调用、跨账号操作号隔离、旧无操作号请求、回执读写故障回滚、响应丢失重试。
- 创建资料取消保留表单、双击锁、成功后配置记忆、完整快照先缓存后跳转。
- 千条同时间流水不丢失；结束状态与全部流水一次 setData；相同完整快照不重绘。
- 删除标记、本人隐藏、本人移出、非法时长及其他用户统计不受影响。
- 分享固定中性标题与静态封面，资料弹框采用原生组件允许的 class 选择器。

这些测试使用内存数据库和实际云函数/页面入口，不访问生产，也不等于真实微信数据库事务、权限、网络或渲染性能验证。

本轮尝试开发者工具复测时 Mac 锁屏，尚未完成界面回归。发布前仍需实际验证资料输入/头像选择/键盘、长昵称、菜单、首次和重复进入、双账号更新与弱网恢复。没有本轮真机延迟或 P95 数据，不能写“首开已达到某个毫秒数”。

## 部署范围与兼容

相对开发基线，本轮改动五个云函数：

1. `calcSeasonScore`。
2. `recordTransaction`、`createGame`、`getSeasonView`、`deleteGameRecord`。
3. 验证旧前端兼容，再上传新前端。

生产基线未知时先逐函数核对。前一轮 `settleGame/getMyAnalytics` 等若尚未部署，需纳入完整差异，不能只照本轮五项覆盖发布。执行步骤与验收见 [部署指南](DEPLOY.md) 和 [发布清单](RELEASE_CHECKLIST.md)。

- 不新增集合、触发器或前端可读权限。`opReceipts` 继续仅云函数读写。
- `createGame.operationId` 为可选新参数；8–64 字符的有效操作号启用回执，缺失或无效值保留旧创建路径，不拒绝旧请求。
- 新字段只增不删；旧 `mode`、返回字段及数据库字段不改名、不收紧。
- 回退也需保留新前端正在依赖的幂等能力，不把 `createGame` 换回忽略操作号的实现。

实现核对：事务内用 `doc(id).get()` 读取回执，配置 `throwOnNotFound: false` 区分缺文档与真实失败；不在事务内用条件查询。依据 [微信云 SDK 源码](https://github.com/wechat-miniprogram/wx-server-sdk/blob/master/index.js) 与 [CloudBase 事务说明](https://docs.cloudbase.net/en/database/transaction)。实际云端 SDK 版本仍需在部署前核实。
