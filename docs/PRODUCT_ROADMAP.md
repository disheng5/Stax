# 产品现状与后续计划

更新：2026-09-13；代码核对点 `e722a8f`。这里区分“本地已实现”“待验收”和“后续工作”，不把开发完成当作线上生效。

## 产品目标

StaxKit 服务于朋友线下德州游戏的娱乐积分记录。核心是**可信账本与无感同步**，同时保留适度趣味，不侵犯隐私，不增加无用提醒或复杂入口。

优先级：**数据准确 > 体验 > 性能**。产品调性：简单清晰、使用丝滑、有设计巧思。任何新功能都不能以牺牲数据正确或完整缓存体验为代价。

## 本地已实现

| 范围 | 当前能力 |
| --- | --- |
| 首页与创建 | Hold'em, held right.、每日一字、底部语录、直接分享；常用积分配置、娱乐积分名称与更多设置 |
| 参与流程 | 微信邀请进入；新用户原地补昵称头像并继续加入，不设手输邀请码入口 |
| 记账 | 买入、代记、结算修正、费用留痕；原始事实与撤销分别表达 |
| 流水 | 全部倒序呈现，不跨日分组、不折叠早期记录；完整分页成功后一次更新 |
| 结算 | 全员结算自动结束，三小时内修正；费用与积分分离，账差如实显示 |
| 积分榜 | 前三荣誉、成员列表、本人数据与本人记录；榜主管理权限单独处理 |
| 战绩 | 概览与趋势，人数/买入次数/星期/位置维度；座位缺失归“未记录” |
| 趋势解读 | 真实窗口观察、温和的决策视角、三十条技巧轮换；本地生成，不等待大模型 |
| 缓存与同步 | 完整房间快照、最近五场预热、相同数据不重绘、可见页订阅与断线恢复 |
| 正确性 | 弱网队列保留新操作并按账号隔离；旧重算不覆盖新结果；派生统计失败可补算 |
| 分享隐私 | 固定中性标题与品牌封面，不把个人或房间统计放进分享预览 |

独立旧维度页仍保留“对手”入口及兼容字段；战绩主页面使用四个维度。不要把兼容保留的入口当作本轮新设计，也不要据此增加他人盈亏分析。

撤销目前保留云端兼容处理与流水呈现，但详情模板没有可见操作入口。是否恢复入口需要单独确认，不视作当前界面已可用功能。

## 发布前必须完成

1. **旧前端兼容验收。** 本地直连生产，先核实各云函数部署版本和变更范围，验证费用、加入、结算、收局与纠错。
2. **双机与弱网验收。** 记录第一次和重复进入的完整可读时间、setData 次数/体积、同步延迟及录屏；覆盖多人操作、头像更新、断网恢复和全部流水。
3. **补算链路。** 核实触发器、索引和函数超时；确认核心结算已成功但派生失败时能够恢复。
4. **隐私与资料。** 验证分享卡片、新用户原地补资料、赛季越界拒绝、退出后的缓存处理；公开说明不得超出实际权限边界。
5. **发布材料。** 对齐版本号、截图、隐私披露、测试账号说明，保存源码与云函数逐项版本记录。

没有真实测量前，不写“P95 已低于 500ms”“首开已秒开”等结论。当前自动测试验证的是特定正确性与渲染行为，不是云端网络时延。

## 下一步：按独立问题推进

### 1. 逐步闭合读取权限

先盘点旧客户端对 games、transactions、seasons 和用户资料的直读依赖，再迁移受控读取与最小变更信号。不得直接关闭旧权限，也不得通过开放整份资料文档解决头像同步。

验收重点是“不应读取的数据不下发”，而不只是前端隐藏。房间主动分享与积分榜成员身份是不同的授权场景，分别设计。

### 2. 用测量驱动性能

先收集首开、暖开、跨场切换和同步耗时，再定位剩余瓶颈。优先减少重复读取、无变化渲染和串行等待；不添加打断缓存路径的骨架屏，不以常驻高频轮询换取表面实时。

近期列表订阅目前覆盖二十场，超出窗口的旧记录管理员修改不保证立即触发。只有实际需求出现时，再扩展变更信号，避免先扩大读取成本。

### 3. 补齐长期数据治理

核对历史派生统计漂移时，先对原始记录做只读审计，列出差异并确认口径，再单独授权重建。不能根据账差猜测某位玩家记错，也不能自动改写其剩余积分。

“正式对局”的测试排除不能只看名称；当前个人分析按本人可见记录计算。若需要产品化正式/测试标记，先明确历史迁移与权限，再单独迭代。

### 4. 内容与小体验的维护

继续维护中性、具体的技巧内容，保留阅读轮换和同页稳定性。只根据记录中已有信息陈述事实；积分本身不支持打法、心理状态或逐手位置的诊断。

在真实设备上处理明确的排版问题，如长昵称、分隔线、触控与键盘避让；每项独立验证，不顺带重做已有页面。

## 明确不做

- 手动输入邀请码、陌生人匹配、聊天或信息流。
- 沿用玩家“再开一局”及无关奖励系统。
- 删除首页底部语录或把便捷分享只藏进微信菜单。
- 截断或默认折叠流水，要求用户进入更深层才能看完账。
- 账不平时再加“请核对剩余积分”等重复提醒或自动纠错面板。
- 用积分高低推断玩家水平、性格，公开负向标签或不必要的他人数据。
- 为了“更有趣”而把短期波动写成确定结论或鼓励追赶结果。

## 开发方式

一次完成一个可验收单元：失败用例 → 定点修复 → 回归 → 小步提交 → 明确部署范围 → 双机验收。保持 [开发契约](../AGENTS.md)，优先延续已有稳定模式。
