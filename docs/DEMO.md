## 两种环境

| 模式 | 启用方式 | 范围 |
| --- | --- | --- |
| 真实云，当前默认 | `ENV_ID = 'cloud1-d7gykoaktfc01fbf0'` | 连接共享生产，操作可能写入真实数据 |
| 本地 Mock | `ENV_ID = 'STAX_REPLACE_ME_BEFORE_DEPLOY'` | 内存业务数据库，不能验证多设备真实同步 |

仅阅读界面或跑演示，优先用 Mock。需要生产双机验收时，先获得测试操作授权，不拿真实朋友局试错。

## 本地 Mock

1. 在独立本地工作副本中，将 `miniprogram/app.js` 的 `ENV_ID` 临时改为占位值。不要把该配置提交或上传。
2. 导入项目并编译，控制台应出现 `[cloud-mock] installed`。
3. 模拟数据包含五场历史记录、一场进行中的记录及示例用户，具体数值以 `miniprogram/utils/mock-data.js` 为准。
4. “我的”中可使用“重置 Demo 数据”，恢复内存种子。
5. 退出演示前恢复实际环境配置，再检查 Git 差异与上传范围。

Mock 业务数据在当前运行时内存中；页面缓存和阅读轮换等本地存储可能跨编译保留。不要把“重编译”当作完整缓存清理。Mock 的 watch 与事务行为也不等同云平台。

无需打开开发工具即可执行隔离回归：

```bash
npm run check
npm run lint
```

## 双机主流程

以下只用于经授权的独立测试记录。账号 A 是房主，账号 B/C 为其他成员。开发者工具切换测试号不等于验证真实多账号身份；使用实际有访问权限的测试账号。

### 创建与邀请

1. A 从首页点“创建积分记录”，用默认每份 500、小盲/大盲 5/5、战绩换算 1:1。
2. 创建后进入详情，通过“邀请”分享给 B/C；不要手输邀请码。
3. B 作为新用户先查看，点“上桌”后在当前页补昵称、选择头像、填写初始手数并加入。
4. C 以已有资料加入，确认两端成员、座位和买入信息对应。
5. 检查分享卡片是中性描述与固定品牌图，不含房间或个人统计。

### 买入与留痕

1. 为便于核算，让 A/B/C 各初始买入一手，即各 500。
2. B 自己补买一手；房间内其累计两手、1000，流水带补买后的总手数。
3. A 为 C 补买一手；检查操作人是 A、被记录玩家是 C。
4. 默认共享权限下成员可自己买入，也可代提成员结算；代买、移出等以服务端权限为准。关闭共享后核对普通成员不能继续操作。

当前详情模板没有绑定撤销入口，不能通过成员菜单完成撤销。撤销处理函数、云端兼容能力与流水展示仍保留，相关账目回退通过自动回归验证，不在这段界面演示中执行。

### 费用与结算

此时买入额为 A 500、B 1000、C 1000，合计 2500。费用总额设 60，分摊选“水上比例”。

| 玩家 | 累计买入 | 结算剩余 | 本局盈亏 |
| --- | ---: | ---: | ---: |
| A | 500 | 800 | +300 |
| B | 1000 | 900 | -100 |
| C | 1000 | 800 | -200 |

- 各成员通过“结算”或点成员提交剩余积分，全员完成后自动结束，不再点“最终结算”。
- 盈亏合计为零，费用 60 单独由 A 分摊；A 的积分盈亏仍是 +300，不变成 +240。
- 在三小时窗口内把 A 的剩余暂改为 790，核对显示真实账差 -10；再改回 800。应用不猜测谁记错，也不自动修正原始账目。
- 两端核对流水、费用摘要、结算结果和个人战绩。

### 战绩与趋势

1. “我的”→“战绩 & 分析”，检查概览和历史记录。
2. 切换人数、买入次数、星期、位置；位置来自各场已记录的座位号，旧场缺失则“未记录”。
3. “买入次数”当前按 `buyInCount` 分桶，该字段随买入手数累计，不等于请求次数。
4. 满五场时展开趋势解读；同页折叠展开不变，读过后退出重进轮换下一条技巧。
5. 后台同步相同数据不重绘、不同数据更新真实观察，不切换正在阅读的技巧。

### 积分榜

通过微信邀请加入同一积分榜，验证前三荣誉、成员名单、本人记录与榜主管理权限。非参与者不会仅因同属积分榜就在普通成员视图看到他人的比赛；主动转发的房间邀请仍按分享查看规则工作。

这属于页面和接口验收，不代表底层数据库权限已全部隔离，边界见 [云资源说明](CLOUD_SETUP.md#数据权限不要照抄旧规则)。

## 必须另外测的异常

- 多于二十条、一百条流水；中间分页失败后不缩短已有完整列表。
- 弱网写入后重放，同时再新增操作；不丢单、不重复。
- A 修改结算、B 留在详情/战绩/积分榜；A 更新头像昵称、B 留在旧记录。
- 初次打开、第二次打开、五场互切、断网重连与切回前台。
- 统计补算失败后的恢复；只能在内存测试或经批准的隔离条件中注入故障，不能破坏生产服务。
- 费用弹框、资料弹框、长昵称和完整流水的真机排版。

完整清单见 [发布验收](RELEASE_CHECKLIST.md)。不再承诺“八分钟覆盖全部能力”或用单机 Mock 代替双机验收。
