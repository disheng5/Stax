# 部署与提审流程

核对日期：2026-09-13；适用于当前开发分支，不是已发布版本清单。

`0.3.4` 已有逐步 [手动发布流程与实际状态](RELEASE_0.3.4.md#手动发布步骤)，包含本次五个云函数、版本号及部署签名错误记录。本文件保留通用发布约束。

## 开始前

- 先读 [开发契约](../AGENTS.md) 和 [云资源说明](CLOUD_SETUP.md)。
- 当前开发直连生产。修改本地文件不等于发布；但部署云函数会立即影响旧线上前端。
- 自动测试通过不是部署授权。确认部署对象、时间、负责人和回退路径后再动生产。
- 微信主体、类目、认证、收费、可用能力及审核要求，以当前管理后台与平台官方说明为准，不沿用旧文档的固定价格或保证通过说法。

## 本地准备

1. 导入包含 `project.config.json` 的仓库根目录，核实打开的不是其他克隆或工作树。
2. 保留现有 AppID 与 `ENV_ID`，除非明确部署另一套小程序。
3. 本轮测试使用 Node.js `v24.18.0`；安装依赖并检查：

```bash
git status --short --branch
npm ci
npm run check
npm run lint
git diff --check
```

`check` 包含单元、函数入口/页面回归、Mock E2E 和文案扫描，不会部署或写入生产。

本地调试出现旧画面时，先核对目录和分支，再关闭热重载、清除编译缓存并重新编译。不要以清空全部本地数据作为默认办法，以免影响待提交记录与缓存体验验证。

## 云端变更

1. 盘点当前已部署版本与八个集合、查询索引、安全规则。已有环境不重新初始化，权限方案见 [云资源说明](CLOUD_SETUP.md)。
2. 按每个函数的实际部署基线检查 diff；若基线未知，先记录“待核实”，不能凭提交时间或截图认定一致。
3. 相对本轮开发基线 `5e0b4ea`，函数增量为 `calcSeasonScore` → `recordTransaction/createGame/getSeasonView/deleteGameRecord`。实际生产若未包含前一轮改动，还需核对 `getMyAnalytics/settleGame` 等差异，不能把开发基线当作部署记录。细节见 [本轮部署依赖](CLOUD_SETUP.md#本轮部署依赖)。
4. 上传整个函数目录，核实共享纯函数、依赖和 config 均在包内；确认补算触发器实际启用与超时足够。
5. 用现有已发布前端验证原调用：创建、邀请加入、费用、结算、收局、三小时内修正。旧 mode、`settledCount/checkedOutCount`、`rankings.winRate` 等必须保持兼容。
6. 确认核心账目与派生统计都正确，再进入新前端验收。

不要因为有旧客户端就跳过鉴权，也不要通过收紧旧参数、删除字段或关闭直读权限来实现“升级”。

## 新前端验收

按 [发布清单](RELEASE_CHECKLIST.md) 执行。至少包含两个账号的共享记录、弱网恢复、完整流水、重复进入、资料更新、分享隐私和趋势轮换。

只使用经授权的测试记录。应用不按“测试”名称自动排除统计；测试结束后按实际业务规则隐藏、删除或排除，不影响真实朋友局。

浏览器截图与内存 Mock 不能替代微信输入、头像选择、键盘、数据库权限和真实网络验收。不要未经测量宣称首开或同步已达到某个毫秒数。

## 上传与提审

1. 明确本次小程序版本号。`0.3.4` 发布准备已统一根包、锁文件和关于页；未来发版仍需对照微信后台版本，不能仅凭仓库标识推断线上版本。
2. 记录前端 commit、上传时间、版本号；分别记录各云函数实际部署 commit、时间、触发器和配置变更。
3. 上传前确认不是 Mock 环境，使用正常域名校验配置，未打包真实导出数据、日志、密钥或无关测试产物。
4. 在微信管理后台提交审核，名称、主体、类目、隐私声明与功能截图按实际情况填写。
5. 简介可围绕“朋友局娱乐积分记录、费用分摊与个人战绩分析”，不写尚未上线的能力。
6. 测试说明使用“账号 A 创建积分记录并分享，账号 B 打开邀请后查看或加入”，不要求手动输入邀请码。
7. 截图使用虚构且已获授权的演示数据，覆盖首页、创建、记录详情、积分榜、战绩分析及必要弹框。
8. [隐私草案](PRIVACY.md) 尚需补齐运营主体、有效联系方式及平台披露核对，不可原样宣称已生效。

审核通过后仍需明确执行发布。上传、提交审核和正式发布是不同状态。

## 发布与回退记录

建议在实际发布时保存以下信息，不预填未知线上状态：

| 项目 | 应记录内容 |
| --- | --- |
| 小程序 | 版本号、源码 commit、上传/审核/发布时间 |
| 云函数 | 每个函数的 commit、部署时间、依赖和配置 |
| 云资源 | 索引、安全规则、定时器变更与核验结果 |
| 验收 | 设备、微信版本、账号角色、网络条件及结果 |
| 回退 | 已验证的前端包与函数版本、需要保留的新增字段 |

Git 回退不会自动回退云函数或数据库。出问题时优先停止扩大发布范围；兼容性回退也要保留已写入字段，不执行破坏性数据库“还原”。

新前端上传后，不应把 `createGame` 回退到忽略 `operationId` 的旧实现，否则同一创建请求的重试可能重复建房。优先修补并保留回执契约。当前创建请求号仅在页面实例存续时复用，不承诺跨重启恢复创建请求。
